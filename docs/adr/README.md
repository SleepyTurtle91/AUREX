# Architecture Decision Records

ADRs document material architectural decisions and their consequences.

## Format

Each ADR should include:

- Number and title.
- Status: proposed, accepted, superseded or rejected.
- Context and problem.
- Decision.
- Consequences and trade-offs.
- Alternatives considered.
- Related decisions.

## Decision discipline

Do not treat a proposal in a README, roadmap or discussion as an accepted technical decision. Update this index when an ADR is created or its status changes.
